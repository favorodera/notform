`notform-nuxt`{lang="ts-type"} is the official Nuxt module for NotForm. It wraps the manual installation steps covered in [Installation](/getting-started/installation) into a single Nuxt module: instead of importing `useNotForm`{lang="ts-type"}, `<NotForm>`{lang="vue"}, `<NotField>`{lang="vue"}, `<NotArrayField>`{lang="vue"}, and `<NotMessage>`{lang="vue"} yourself in every file, the module registers them as Nuxt auto-imports, injects their types globally, and confirms they work correctly with Nuxt's SSR rendering — all with no extra configuration on your part.

::note
This page assumes you're building a Nuxt application. If you're using plain Vue or Vite instead, follow [Installation](/getting-started/installation) — `notform-nuxt`{lang="ts-type"} is Nuxt-only.
::

## Installation

The module is published to the official Nuxt Modules Registry, so it can be added with a single Nuxt CLI command rather than installing the package and editing `nuxt.config.ts`{lang="ts-type"} by hand:

::code-group
```bash [npx]
npx nuxi module add notform
```
```bash [pnpm]
pnpm dlx nuxi module add notform
```
```bash [bun]
bunx nuxi module add notform
```
```bash [yarn]
yarn dlx nuxi module add notform
```
::

::note
This command installs `notform-nuxt`{lang="ts-type"} and adds it to the `modules`{lang="ts-type"} array in your `nuxt.config.ts`{lang="ts-type"} automatically. It does not install a validation library for you — NotForm still validates through [Standard Schema](https://standardschema.dev), so you need to add one yourself (e.g. `zod`{lang="ts-type"}), the same as in the manual [Installation](/getting-started/installation) guide.
::

::code-group
```bash [npm]
npm install zod
```
```bash [pnpm]
pnpm add zod
```
```bash [bun]
bun add zod
```
```bash [yarn]
yarn add zod
```
::

## Manual Setup

If you'd rather not use the Nuxt CLI — for example, in a monorepo where you manage `nuxt.config.ts`{lang="ts-type"} by hand, or in a restricted environment where `nuxi module add`{lang="text"} can't reach the registry — you can install and register the module yourself.

Add the dependency:

::code-group
```bash [npm]
npm add notform-nuxt
```
```bash [pnpm]
pnpm add notform-nuxt
```
```bash [bun]
bun add notform-nuxt
```
```bash [yarn]
yarn add notform-nuxt
```
::

Then add it to your `nuxt.config.ts`{lang="ts-type"}:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['notform-nuxt'],
})
```

This has the exact same effect as running the CLI command above — the module doesn't behave any differently depending on how it was registered.

## Features

### Auto-imports

Once the module is registered, every core component and composable is available globally in your `.vue`{lang="text"} files, without an `import`{lang="ts-type"} statement.

Compare the manual setup from [Installation](/getting-started/installation):

```vue [WithoutModule.vue]
<script setup lang="ts">
import { NotField, NotForm, NotMessage, useNotForm } from 'notform'
import { z } from 'zod'

const form = useNotForm({ /* ... */ })
</script>
```

to the same file with `notform-nuxt`{lang="ts-type"} installed:

```vue [WithModule.vue]
<script setup lang="ts">
import { z } from 'zod'

const form = useNotForm({ /* ... */ })
</script>
```

`useNotForm`{lang="ts-type"}, `<NotForm>`{lang="vue"}, `<NotField>`{lang="vue"}, `<NotArrayField>`{lang="vue"}, and `<NotMessage>`{lang="vue"} are all resolved automatically — only your validation library still needs a manual import, since that's a separate package the module doesn't own.

::field-group
  :::field{name="useNotForm" type="Composable"}
  The core form management composable.
  :::

  :::field{name="<NotForm>" type="Component"}
  Context provider and `<form>`{lang="vue"} wrapper.
  :::

  :::field{name="<NotField>" type="Component"}
  Renderless wrapper for single fields.
  :::

  :::field{name="<NotMessage>" type="Component"}
  Error message renderer.
  :::

  :::field{name="<NotArrayField>" type="Component"}
  Renderless wrapper for dynamic array fields.
  :::
::

### Type Safety

Auto-imported components and composables still carry their full generic types. `useNotForm<TSchema>`{lang="ts-type"} infers `TSchema`{lang="ts-type"} from the schema you pass it exactly as it would with a manual import, so `form.values`{lang="ts-type"} is typed to your schema's shape, and field `path`{lang="ts-type"} props are checked against it — all without a `types`{lang="ts-type"} array entry or a manual reference to the `notform`{lang="ts-type"} package in your project.

### Server-side Rendering (SSR)

NotForm works with Nuxt's SSR rendering: the form's initial state is computed consistently on both the server-rendered HTML and the client-side Vue instance that takes over from it, so values and validation state don't flash, reset, or mismatch during hydration.

## Next steps

The Nuxt module changes how NotForm's pieces are imported, but not how they're used. Continue to [Quickstart](/getting-started/quickstart) to build your first form — every example there works identically whether you installed NotForm manually or through this module, just without the `import`{lang="ts-type"} line for NotForm itself.
