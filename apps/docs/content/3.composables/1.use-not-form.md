`useNotForm`{lang="ts-type"} is the core composable for creating and managing a NotForm instance.

It connects a Standard Schema-compatible validator to a deeply reactive form state and provides everything needed to manage values, validation, field interaction, errors, submission, and reset behavior.

The returned form instance can be used directly or provided to [`<NotForm>`{lang="ts-type"}](/components/not-form) for use by descendant field components.

## API

### Signature

```ts
function useNotForm<TSchema extends ObjectSchema>(
  config: UseNotFormConfig<TSchema>
): NotFormAPI<TSchema>
```

### Parameters

::field-group
  :::field{name="config" type="UseNotFormConfig<TSchema>" required}
  Schema, initial values/errors, and submit handler configuration.

  <br><br>
  The configuration options are:

    ::field-group
      :::field{name="schema" type="MaybeRefOrGetter<TSchema>" required}
      Schema used to parse and validate values.

      <br><br>

      It can be provided directly, as a ref to a schema or as a function that returns a schema.

      ```ts
      import { z } from 'zod'

      const schema = z.object({
        email: z.email(),
      })

      const form = useNotForm({
        schema,
      })
      ```

        ::caution
        The schema must be Standard Schema compatible whose input is an object.
        ::
      :::

      :::field{name="initialValues" type="DeepPartial<InferInput<TSchema>>"}
      Starting or initial values for the form.

      <br><br>

      The supplied values become the form's initial baseline for form values and are used for:

      * populating `form.values`{lang="ts-type"}
      * dirty state comparisons
      * `form.reset()`{lang="ts-type"}

      ```ts
      const form = useNotForm({
        schema,
        initialValues: {
          email: 'user@example.com',
          profile: {
            name: 'Jane',
          },
        },
      })
      ```

        ::note
        When `initialValues`{lang="ts-type"} is omitted, the form starts from an empty object.
        ::
      :::

      :::field{name="initialErrors" type="Array<Issue>"}
      Issues shown before the first validation run.

      <br><br>

      This is useful when a form needs to start with errors returned from another source, such as previously persisted validation state.

      <br><br>

      The supplied values become the form's initial baseline for validation errors and are used for:

      * populating `form.errors`{lang="ts-type"}
      * dirty state comparisons
      * `form.reset()`{lang="ts-type"}

      ```ts
      const form = useNotForm({
        schema,
        initialValues: {
          email: 'user@example.com',
        },
        initialErrors: [{ message: 'Email already taken', path: 'email' }],
      })
      ```

        ::note
        When `initialErrors`{lang="ts-type"} is omitted, the form starts with no issues.
        ::
      :::

      :::field{name="onSubmit" type="(data: InferOutput<TSchema>) => Promise<void> | void"}
      Callback function that is called after a successful submit validation.

      ```ts
      const form = useNotForm({
        schema,
        initialValues: {
          email: 'user@example.com',
        },
        onSubmit(values) {
          console.log(values)
        },
      })
      ```
      :::
    ::
  :::
::

### Return Value

`useNotForm`{lang="ts-type"} returns a `NotFormAPI<TSchema>`{lang="ts-type"} object, which is a reactive form instance with the following properties:

::field-group
  :::field{name="errors" type="Array<Issue>"}
  Issues from the last validation that wrote errors.

  <br><br>

  Each issue contains the path and message supplied by the validation schema.
  :::

  :::field{name="getFieldErrors" type="(path: Paths<TSchema>) => Array<Issue>"}
  Returns all active validation issues associated with a particular field path.
  :::

  :::field{name="isDirty" type="boolean"}
  Indicates if the form values have been changed since the form was initialized.

  ```vue
  <template>
    <div>
      <p v-if="form.isDirty">
        You have unsaved changes.
      </p>
    </div>
  </template>
  ```
  :::

  :::field{name="isSubmitting" type="boolean"}
  Indicates if the form is currently submitting.

  ```vue
  <template>
    <button
      type="submit"
      :disabled="form.isSubmitting"
    >
      {{ form.isSubmitting ? 'Submitting...' : 'Submit' }}
    </button>
  </template>
  ```
  :::

  :::field{name="isTouched" type="boolean"}
  Indicates if any form field has been touched.

  ```vue
  <template>
    <div>
      <p v-if="form.isTouched">
        You have interacted with at least one field.
      </p>
    </div>
  </template>
  ```
  :::

  :::field{name="isValid" type="boolean"}
  Indicates if the form currently has no active validation errors.

  ```vue
  <template>
    <button
      type="submit"
      :disabled="!form.isValid"
    >
      Submit
    </button>
  </template>
  ```

    ::note
    `isValid`{lang="ts-type"} is based on the current `errors`{lang="ts-type"} collection. It does not independently execute validation.
    ::
  :::

  :::field{name="isValidating" type="boolean"}
  Indicates if the form is currently being validated.

  ```vue
  <template>
    <div>
      <p v-if="form.isValidating">
        Validating...
      </p>
    </div>
  </template>
  ```
  :::

  :::field{name="reset" type="(values?: DeepPartial<InferInput<TSchema>>, errors?: Array<Issue>) => void"}
  Restores values/errors to the baseline. Optional arguments become the new baseline.

  <br><br>

  This also resets the dirty, validation, and touch states.

  * **Reset with New values:**
  ```ts
  form.reset({
    email: 'jane@example.com',
    name: 'Jane',
  })
  ```

  * **Reset with New errors:**
  ```ts
  form.reset(
    undefined,
    [
      {
        message: 'Email requires verification.',
        path: ['email'],
      },
    ]
  )
  ```

  * **Reset with both New values and errors:**
  ```ts
  form.reset(
    {
      email: 'jane@example.com',
      name: 'Jane',
    },
    [
      {
        message: 'Email requires verification.',
        path: ['email'],
      },
    ]
  )
  ```

  * **Reset without New values and errors:**
  ```ts
  form.reset()
  ```

    ::note
    Calling `form.reset()`{lang="ts-type"} restores the form to its current baseline. If that baseline has since been updated, `reset()`{lang="ts-type"} restores to the updated values and errors. Otherwise, it falls back to the original `initialValues`{lang="ts-type"} and `initialErrors`{lang="ts-type"}, or to an empty state if neither was provided.
    ::
  :::

  :::field{name="setError" type="(error: Issue) => void"}
  Upserts an issue at the same path, or appends it.

  <br><br>

  Use this when you need to manually manage validation issues for a field, for example, after a server-side validation.

  :::field{name="setValue" type="(path: Paths<TSchema>, value: Get<InferInput<TSchema>, TPath, { strict: false }>) => void"}
  Sets a field value by path.

  <br><br>

  Use this when you need to manually set the value of a field, for example, after a server-side update or custom inputs.

  ```ts
  form.setValue('email', 'jane@example.com')
  ```

    ::note
    Calling `setValue()`{lang="ts-type"} updates the field's value and recomputes `isDirty`{lang="ts-type"} by comparing the new value against the current baseline.
    ::

    ::caution
    `setValue()`{lang="ts-type"} does not trigger validation on its own. Validation still runs only through the field's configured interaction handlers (e.g. `onChange`{lang="ts-type"}, `onBlur`{lang="ts-type"}), so call `validate()`{lang="ts-type"} manually if you need to validate right after a programmatic `setValue()`{lang="ts-type"} call.
    ::
  :::

  :::field{name="submit" type="(event?: SubmitEvent) => Promise<void>"}
  Marks all fields as touched and dirty, validates the complete form, then runs `onSubmit`{lang="ts-type"} when valid.

  <br><br>

  * **Bind it directly to `<NotForm>`{lang="vue"}**:

  ```vue
  <template>
    <NotForm @submit="form.submit">
      <input v-model="form.values.email">

      <button
        type="submit"
        :disabled="form.isSubmitting"
      >
        {{ form.isSubmitting ? 'Submitting...' : 'Submit' }}
      </button>
    </NotForm>
    /template>
  </template>
  ```

  * **Or call programmatically:**

  ```ts
  form.submit()
  ```

    ::note
    If no `onSubmit`{lang="ts-type"} callback was provided, the form still runs validation on submit but has no callback to execute when it succeeds.
    ::
  :::

  :::field{name="validate" type="() => Promise<StandardSchemaV1.Result<InferOutput<TSchema>>>"}
  Validates the entire form against the current schema.

  <br><br>

  On success, the form's errors are cleared and the schema's validated (typed) output is returned. On failure, the returned result contains the validation issues, and those same issues replace the form's current errors.
  :::

  :::field{name="validateField" type="(path: Paths<TSchema>) => Promise<StandardSchemaV1.Result<InferOutput<TSchema>>>"}
  Validates a specific field against the current schema.

  <br><br>

  On success, the field's validated (typed) output is returned. On failure, the returned result contains the validation issues, and those same issues are added to the form's current errors.

  <br><br>

  This is useful when building custom inputs that need to validate themselves without validating the entire form.
  :::

  :::field{name="values" type="InferInput<TSchema>"}
  Deeply reactive object containing the live form values.

  <br><br>

  It can be accessed directly:

  ```ts
  console.log(form.values.email)
  ```

  Or used for two-way binding with v-model:

  ```vue
  <template>
    <input v-model="form.values.email">
  </template>
  ```

  ```vue
  <template>
    <input v-model="form.values.address.city">
  </template>
  ```
  :::
::
