This guide builds a small sign-in form using Vue 3, Zod, and NotForm.

The goal is to show the relationship between the schema, the form instance, and the field components. Once that pattern makes sense, you can use the same structure with other validators and UI systems.

## 1. Define the schema

Start with the data your form accepts.

```ts
import { z } from 'zod'

const schema = z.object({
  email: z.email('Enter a valid email'),
  password: z.string().min(8, 'At least 8 characters'),
})
```

The schema controls validation and provides the types used by NotForm.

## 2. Create the form

Pass the schema to [`useNotForm`](/docs/composables/use-not-form).

```ts
const form = useNotForm({
  onSubmit(values) {
    console.log('Submitted:', values)
  },
  schema,
})
```

Provide `initialValues` when you want explicit starting data:

```ts
const form = useNotForm({
  initialValues: {
    email: '',
    password: '',
  },
  schema,
})
```

## 3. Add the form component

`<NotForm>` renders a native `<form>` and provides the form instance to descendant fields.

```vue
<template>
  <NotForm
    :form="form"
    @submit="form.submit"
    @reset="form.reset()"
  >
  <!-- fields -->
  </NotForm>
</template>
```

`NotForm` prevents the browser's native reset behavior and provides form context. Submit prevention belongs to `form.submit()`, which calls `event.preventDefault()` when it receives the native submit event. Bind both handlers explicitly so the form lifecycle is controlled by NotForm.

## 4. Connect a field

`<NotField>` is renderless. It gives you the field path, field state, errors, and event handlers through its default slot.

```vue
<template>
  <NotField
    v-slot="{ events, path }"
    path="email"
  >
    <label :for="path">Email</label>

    <input
      :id="path"
      v-model="form.values.email"
      v-bind="events"
      type="email"
      autocomplete="email"
    >

    <NotMessage :path="path" />
  </NotField>
</template>
```

You still own the input element. `events` is the bridge between that element and NotForm's interaction and validation lifecycle.

## 5. Add submission state

Because submission state is reactive, use it directly in the template:

```vue
<template>
  <button
    type="submit"
    :disabled="form.isSubmitting"
  >
    {{ form.isSubmitting ? 'Submitting...' : 'Submit' }}
  </button>
</template>
```

The architecture is deliberately small:

```text
schema       → validation and types
useNotForm   → values and lifecycle
NotForm      → native form + context
NotField     → field state + events
NotMessage   → first field error
```

## What happens on submit?

When `form.submit()` runs, NotForm:

1. prevents the browser's default submission
2. marks current fields as touched
3. synchronizes dirty state
4. validates the complete form
5. stores validation issues when invalid
6. calls `onSubmit` with validated output when valid
7. keeps `isSubmitting` active while the submit handler runs

See [Submission](/docs/concepts/submission) for the full lifecycle.
