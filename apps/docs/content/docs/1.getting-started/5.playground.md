The NotForm Playground is an in-browser Vue 3 REPL powered by Monaco Editor, `@vue/repl`{lang="ts-type"}, and Tailwind CSS v4. It gives you a complete sandbox to experiment with form schemas, validation rules, field states, and dynamic array handling in real time.

## Overview

The playground requires zero local installation. Everything runs directly in your browser:

::card-group
  :::app-card{icon="tabler:brand-vue" title="Vue 3 & TypeScript"}
  Full SFC support with `<script setup lang="ts">`{lang="vue"}, Vue 3.5, and Monaco-powered TypeScript auto-completion.
  :::

  :::app-card{icon="custom:logo" title="NotForm Preloaded"}
  `useNotForm`{lang="ts-type"}, `<NotForm>`{lang="vue"}, `<NotField>`{lang="vue"}, `<NotArrayField>`{lang="vue"}, and `<NotMessage>`{lang="vue"} are all pre-configured and ready to import.
  :::

  :::app-card{icon="tabler:shield-check" title="Zod & Standard Schema"}
  `zod`{lang="ts-type"} is available out of the box. Any Standard Schema validator can also be loaded via ESM.
  :::

  :::app-card{icon="tabler:palette" title="Tailwind CSS v4"}
  Pre-loaded styling utilities and theme variables with instant preview synchronization in both light and dark modes.
  :::
::

## Key Workflows

### 1. Prototyping & Live Testing

Start building your form in `App.vue`{lang="ts-type"}. As you edit values, schemas, and template markup, the preview updates immediately. You can test user interactions, submission handlers, validation errors, and array field reordering without spinning up a dev server.

### 2. Sharing Code & Reproducing Bugs

Every change in the playground can be encoded directly into a shareable URL:

1. Click the **Share** button in the playground header.
2. The current code across your tabs is compressed and encoded into the URL hash, and copied to your clipboard.
3. Anyone opening the link will see your exact reproduction state.

::tip
When filing a bug report on [GitHub](https://github.com/favorodera/notform/issues), include a shared Playground link! Having a minimal, live reproduction makes it significantly easier to diagnose and resolve issues quickly.
::

### 3. Testing PRs with pkg.pr.new

Every pull request submitted to the NotForm repository triggers an automated workflow that publishes continuous preview packages to [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new).

You can test pull request builds in two ways:

- **In the Playground**: Update the import map or import directly from the preview package URL generated by `pkg.pr.new`{lang="ts-type"}.
- **In a Local Project**: Install the PR package directly using your package manager:

::code-group
```bash [pnpm]
pnpm add https://pkg.pr.new/notform@<pr-number>
```

```bash [yarn]
yarn add https://pkg.pr.new/notform@<pr-number>.tgz
```

```bash [npm]
npm install https://pkg.pr.new/notform@<pr-number>
```

```bash [bun]
bun add https://pkg.pr.new/notform@<pr-number>
```
::

### 4. Resetting to Starter Template

If you want to clear your current session and restore the default starter code (featuring full name, email, and dynamic interest tags), click the **Reset** button in the playground header.
