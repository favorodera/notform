`<NotArrayField>` is the renderless component for dynamic arrays.

It exposes current items, stable keys, recursive aggregate state, and mutation methods while leaving the row markup entirely to you.

::caution
Always use `item.key` as the Vue `v-for` key. The current index describes position, not identity.
::

A minimal array looks like this:

```vue
<template>
  <NotArrayField
    v-slot="{ append, items, remove }"
    path="tags"
  >
    <div
      v-for="item in items"
      :key="item.key"
    >
      <input
        v-model="form.values.tags[item.index]"
        :name="item.path"
      >

      <button
        type="button"
        @click="remove(item.index)"
      >
        Remove
      </button>
    </div>

    <button
      type="button"
      @click="append('')"
    >
      Add tag
    </button>
  </NotArrayField>
</template>
```

For object items, use `item.path` to build nested field paths:

```vue
<NotField :path="`${item.path}.name`">
  ...
</NotField>
```

## Props

| Prop | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `path` | `Paths<TSchema>` | Yes | — | Typed path of the array field |
| `itemSchema` | `TItemSchema` | No | — | Optional schema used only for mutation value inference |
| `form` | `NotFormAPI<TSchema>` | No | Injected form | Explicit form instance; overrides context |

## `itemSchema`

`itemSchema` is an inference aid. It is not used as a runtime validator.

The array is validated by the main form schema supplied to `useNotForm()`.

## Slot: `default`

| Prop | Type | Description |
| --- | --- | --- |
| `path` | `string` | Current array path |
| `items` | `NotArrayFieldItem<TSchema>[]` | Items with `key`, `index`, and `path` |
| `errors` | `Issue[]` | Issues exactly at the array path |
| `isValid` | `boolean` | Whether the array and all descendants have no issues |
| `isTouched` | `boolean` | Whether the array or a descendant is touched |
| `isDirty` | `boolean` | Whether the array or a descendant differs from baseline |
| `isValidating` | `boolean` | Whether the array or a descendant is validating |
| `append` | `(value) => void` | Add an item to the end |
| `prepend` | `(value) => void` | Add an item to the beginning |
| `insert` | `(index, value) => void` | Insert an item |
| `remove` | `(index) => void` | Remove an item |
| `update` | `(index, value) => void` | Replace an item without changing its key |
| `swap` | `(indexA, indexB) => void` | Exchange two items |
| `move` | `(from, to) => void` | Move an item |

## Mutation methods

### `append`

```ts
append({ email: '', name: '' })
```

Adds an item to the end and gives it a new stable key.

### `prepend`

```ts
prepend({ email: '', name: '' })
```

Adds an item to the beginning and shifts the existing items' nested state with them.

### `insert`

```ts
insert(2, { email: '', name: '' })
```

The insertion position is normalized into the valid range.

### `remove`

```ts
remove(1)
```

Removes the item, its key, and state belonging to that item. Later items shift left and retain their state.

### `update`

```ts
update(1, {
  email: 'jane@example.com',
  name: 'Jane',
})
```

Replaces the value without changing the item's key or position.

### `swap`

```ts
swap(0, 1)
```

Exchanges the items, keys, and nested touched, dirty, and error state.

### `move`

```ts
move(0, 3)
```

Moves one item and shifts the items between the source and destination. The destination is normalized to the current array bounds.

## Item identity

Use the item object rather than reconstructing paths from raw indexes when possible:

```vue
<template>
  <div
    v-for="item in items"
    :key="item.key"
  >
    <NotField :path="`${item.path}.name`" />
  </div>
</template>
```

`item.path` always reflects the item's current index.

## Recursive state

The aggregate flags include the entire array subtree.

An error at:

```text
users.2.profile.email
```

makes `isValid` false for the `users` array even though `errors` is empty when the issue is not reported directly at `users`.

The same recursive rule applies to touched, dirty, and validating state.

## Direct array mutation

Avoid changing the array with `push()`, `splice()`, or direct index assignment when you need row identity and state preservation:

```ts
form.values.users.push(user)
```

Use the NotArrayField methods instead:

```ts
append(user)
```

The mutation methods update values, keys, dirty state, and nested form state together.

## Async validation

Structural mutations invalidate older in-flight validation results. This prevents a stale response from being attached to a different item after a remove, insert, swap, or move.
