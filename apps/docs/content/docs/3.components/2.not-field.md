`<NotField>` connects one schema path to the form instance.

It renders nothing. Its default slot exposes the field path, validation errors, state flags, and event handlers so you can use your own input element or component.

The core pattern is:

```vue
<template>
  <NotField
    v-slot="{ events, path }"
    path="email"
  >
    <label :for="path">Email</label>

    <input
      :id="path"
      v-model="form.values.email"
      v-bind="events"
      type="email"
    >

    <NotMessage :path="path" />
  </NotField>
</template>
```

`NotField` owns no input markup. You decide which element receives the value and event handlers.

## Props

| Prop | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `path` | `Paths<TSchema>` | Yes | — | Typed dot path for the field |
| `form` | `NotFormAPI<TSchema>` | No | Injected form | Explicit form instance; overrides context |
| `validateOn` | `Partial<Record<ValidationTrigger, boolean>>` | No | `{ onBlur: true, onChange: true }` | Automatic validation triggers |
| `validationMode` | `'eager' \| 'lazy'` | No | `'eager'` | Revalidation behavior while invalid |
| `debounce` | `number` | No | — | Delay in ms for input/change validation |

## `validateOn`

| Trigger | Behavior |
| --- | --- |
| `onBlur` | Validate when the input blurs |
| `onChange` | Validate from the change handler |
| `onInput` | Validate from the input handler |
| `onMount` | Validate once after mount |

The configuration is merged over the defaults, so you can change one trigger without redefining the others.

```vue
<template>
  <NotField
    path="email"
    :validate-on="{ onBlur: true, onChange: false }"
  >
    ...
  </NotField>
</template>
```

`onMount` is not included in `events` because it is not a DOM event. NotForm runs it automatically after the component mounts.

## `validationMode`

`eager` revalidates an invalid field on enabled input/change triggers.

`lazy` does not continuously revalidate while editing an invalid field, making blur or explicit validation the normal feedback point.

## `debounce`

Use `debounce` for input or change validation that should wait for a pause in typing:

```vue
<template>
  <NotField
    path="username"
    :debounce="300"
  >
    ...
  </NotField>
</template>
```

Blur validation runs immediately and cancels a pending debounced run.

## Slot: `default`

The slot exposes the field state.

| Prop | Type | Description |
| --- | --- | --- |
| `path` | `string` | Current field path |
| `events` | `Record<'onBlur' \| 'onChange' \| 'onInput', () => void>` | Handlers to bind to the input |
| `errors` | `Issue[]` | Issues whose path exactly matches the field |
| `isDirty` | `boolean` | Whether the field differs from its baseline |
| `isTouched` | `boolean` | Whether the field has been touched |
| `isValid` | `boolean` | Whether the field currently has no errors |
| `isValidating` | `boolean` | Whether the field is currently validating |

Example:

```vue
<template>
  <NotField
    v-slot="{ errors, events, isDirty, isTouched, path }"
    path="email"
  >
    <input
      :id="path"
      v-model="form.values.email"
      v-bind="events"
    >

    <p v-if="isTouched && errors.length > 0">
      {{ errors[0].message }}
    </p>

    <small v-if="isDirty">Unsaved changes</small>
  </NotField>
</template>
```

## Event handlers

The recommended pattern is to bind the complete object:

```vue
<template>
  <input v-bind="events">
</template>
```

The handlers synchronize interaction state and trigger field validation according to `validateOn`, `validationMode`, and `debounce`.

Programmatic changes are separate. `form.setValue()` updates the value and dirty state, but it does not validate the field automatically.

## Nested fields

Paths follow the schema's input structure:

```vue
<template>
  <NotField path="profile.email">
    ...
  </NotField>
</template>
```

For array items, use the item path exposed by `<NotArrayField>`:

```vue
<template>
  <NotField :path="`${item.path}.name`">
    ...
  </NotField>
</template>
```

## Using an explicit form

Outside a `<NotForm>` ancestor, provide the form directly:

```vue
<template>
  <NotField
    :form="form"
    path="email"
  >
    ...
  </NotField>
</template>
```

The explicit form also lets one field intentionally use a different form when nested under another form context.
