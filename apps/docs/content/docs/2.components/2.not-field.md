title: NotField

`<NotField>` connects a schema path to form state. Its default slot exposes field status, errors, and event handlers without rendering markup.

## API Reference

### Props

::field-group
  :::field{name="path" type="Paths<TSchema>" required}
  Schema-derived dot path of the field, such as `email` or `user.email`. The slot exposes the path for labels and related elements.
  :::

  :::field{name="form" type="NotFormAPI<TSchema>"}
  Optional form instance. Overrides the nearest `<NotForm>` provider; required when no provider exists.
  :::

  :::field{name="validateOn" type="Partial<Record<ValidationTrigger, boolean>>"}
  Partial overrides for `onBlur`, `onChange`, `onInput`, and `onMount`. Blur and change default to `true`; unspecified triggers keep their defaults. `onMount` validates once after the field mounts and is not included in the `events` slot prop.
  :::

  :::field{name="validationMode" type="'eager' | 'lazy'"}
  Defaults to `eager`. Eager mode revalidates on enabled input or change triggers only while the field is invalid. Lazy mode validates on blur or submit, even when input/change triggers are enabled.
  :::

  :::field{name="debounce" type="number"}
  Delays enabled input/change validation by the specified milliseconds. Omit it or pass `0` to disable. Blur validation is immediate.
  :::
::

### Slots

#### `default`
The default slot receives the complete field state and event handlers.

```vue
<template>
  <NotField
    v-slot="slotProps"
    path="email"
  >
    ...
  </NotField>
</template>
```

::field-group
  :::field{name="path" type="string"}
  Dot path of this field.

  <br><br>

  Useful for labels, inputs, IDs, messages, and other field-specific elements.

  ```vue
  <template>
    <NotField
      v-slot="{ path }"
      path="email"
    >
      <label :for="path">Email</label>
  
      <input :id="path">
    </NotField>
  </template>
  ```
  :::

  :::field{name="errors" type="Array<Issue>"}
  Validation issues for this field path.

  <br><br>

  It contains all validation issues reported for the field during the most recent validation run.

  ```vue
  <template>
    <NotField
      v-slot="{ errors }"
      path="email"
    >
      <input v-model="form.values.email">
    </NotField>  
  </template>    
  ```  
  :::  
  
  ### Slots

  #### `default`

  The default slot receives:

  ::field-group
    :::field{name="path" type="string"}
    Current dot path. Use it to associate labels, inputs, and messages.
    :::

    :::field{name="errors" type="Array<Issue>"}
    Issues reported at this exact field path.
    :::

    :::field{name="isValid" type="boolean"}
    `true` when the field has no issues.
    :::

    :::field{name="isTouched" type="boolean"}
    Whether the user has blurred the field.
    :::

    :::field{name="isDirty" type="boolean"}
    Whether the field value differs from its baseline.
    :::

    :::field{name="isValidating" type="boolean"}
    Whether the field currently has a validation run.
    :::

    :::field{name="events" type="Record<ExcludeStrict<ValidationTrigger, 'onMount'>, () => void>"}
    `onBlur`, `onChange`, and `onInput` handlers. Bind all three to a native input with `v-bind="events"`, or map individual handlers for a custom component. These callbacks take no event argument. `onMount` is configured through `validateOn` and runs automatically.
    :::
  ::

  For a custom control, map its events to the matching handlers:

  ```vue
  <NotField v-slot="{ events }" path="country">
    <CustomCombobox
      @focusout="events.onBlur"
      @pick="events.onChange"
    />
  </NotField>
  ```
