NotForm is designed to work with any validation library that implements the [Standard Schema](https://standardschema.dev) interface. This means you can use Zod, Valibot, ArkType, or any other compliant validator without being locked into a specific ecosystem.

## What is Standard Schema?

Standard Schema is a specification that defines a common interface for schema validation libraries. This allows libraries like NotForm to work with multiple validation implementations without needing to write adapters for each one.

## Supported Validators

NotForm works seamlessly with these popular validators:

::code-group
```ts [Zod]
import { z } from 'zod'

const schema = z.object({
  email: z.email('Invalid email'),
  age: z.number().min(18, 'Must be 18 or older'),
})
```
```ts [Valibot]
import { object, string, number, minValue } from 'valibot'

const schema = object({
  email: string('Invalid email'),
  age: number('Invalid age', [minValue(18, 'Must be 18 or older')]),
})
```
```ts [ArkType]
import { type } from 'arktype'

const schema = type({
  email: 'email',
  age: 'number>=18',
})
```
::

## Defining Your Schema

Pass your schema to `useNotForm` and NotForm will automatically infer the types for your form values.

```ts
import { z } from 'zod'

const schema = z.object({
  username: z.string().min(3, 'Username must be at least 3 characters'),
  email: z.email('Invalid email address'),
  age: z.number().min(18, 'Must be 18 or older'),
  bio: z.string().optional(),
})

const form = useNotForm({
  schema,
  onSubmit(values) {
    // `values` is automatically typed as:
    // { username: string, email: string, age: number, bio?: string }
    console.log(values)
  },
})
```

## Validation Modes

NotForm supports multiple validation triggers. You can configure when validation runs per-field or globally:

- **blur** - Validate when a field loses focus (default)
- **input** - Validate on every keystroke
- **change** - Validate when the value changes
- **focus** - Validate when a field gains focus
- **submit** - Validate only on form submission

See the [Validation Modes](/advanced/validation-modes) guide for detailed configuration.

## Async Validation

Standard Schema supports async validation, which NotForm handles automatically:

```ts
const schema = z.object({
  username: z.string().refine(
    async (value) => {
      const response = await fetch(`/api/check-username?username=${value}`)
      const data = await response.json()
      return data.available
    },
    { message: 'Username is already taken' }
  ),
})
```

## Custom Error Messages

Your validation library handles error messages. NotForm simply displays whatever message your schema returns:

```ts
const schema = z.object({
  password: z.string()
    .min(8, 'Password must be at least 8 characters')
    .regex(/[A-Z]/, 'Must contain at least one uppercase letter')
    .regex(/[0-9]/, 'Must contain at least one number'),
})
```
