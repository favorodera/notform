NotForm gives you fine-grained control over when validation runs. You can configure validation triggers globally, per-field, or per validation mode.

## Default Behavior

By default, NotForm validates fields on **blur**—when a user leaves a field. This provides a good balance between immediate feedback and not annoying the user with errors while they're still typing.

## Validation Triggers

NotForm supports five validation triggers:

| Trigger | When it fires | Use case |
|---------|---------------|----------|
| **blur** | When a field loses focus | Default. Good balance of feedback |
| **input** | On every keystroke | Immediate feedback, can be noisy |
| **change** | When the value changes | Less frequent than input |
| **focus** | When a field gains focus | Rare, for specific use cases |
| **submit** | Only on form submission | Minimal validation feedback |

## Configuring Validation Mode

You can set the validation mode when initializing the form:

```ts
const form = useNotForm({
  schema,
  validationMode: 'input', // Validate on every keystroke
  onSubmit(values) {
    console.log(values)
  },
})
```

## Per-Field Validation Mode

You can override the global validation mode for specific fields:

```vue
<NotField 
  v-slot="{ events, path }" 
  path="email"
  validation-mode="input"
>
  <input :id="path" v-model="form.values.email" v-bind="events" />
  <NotMessage :path="path" />
</NotField>
```

This is useful for fields where you want immediate feedback (like email validation) while keeping other fields on blur.

## Validation on Submit

Regardless of your validation mode, NotForm always validates the entire form on submission. This ensures that even if a user never touches a field, invalid data won't be submitted.

```ts
const form = useNotForm({
  schema,
  validationMode: 'blur', // or any other mode
  onSubmit(values) {
    // This only runs if the entire form is valid
    console.log('Valid form submitted:', values)
  },
})
```

## Disabling Validation

To disable automatic validation entirely and only validate on submit:

```ts
const form = useNotForm({
  schema,
  validationMode: 'submit',
  onSubmit(values) {
    console.log(values)
  },
})
```

## Manual Validation

You can manually trigger validation for a specific field or the entire form:

```ts
// Validate a specific field
form.validateField('email')

// Validate the entire form
form.validate()
```

## Async Validation

Validation modes work seamlessly with async validation. When using async validators (like checking username availability), the validation runs according to your configured mode:

```ts
const schema = z.object({
  username: z.string().refine(
    async (value) => {
      const response = await fetch(`/api/check-username?username=${value}`)
      const data = await response.json()
      return data.available
    },
    { message: 'Username is already taken' }
  ),
})

const form = useNotForm({
  schema,
  validationMode: 'blur', // Async validation runs on blur
  onSubmit(values) {
    console.log(values)
  },
})
```

## Best Practices

- **Use blur for most fields** - It provides feedback without being annoying
- **Use input for critical fields** - Like email or password confirmation where immediate feedback is helpful
- **Use submit for simple forms** - When you want minimal validation feedback
- **Consider async validation** - Async validators can be slow, so avoid using them with `input` mode
