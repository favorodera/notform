Forms often need to display errors returned from a server after submission. NotForm provides the `setErrors` method to apply server-side validation errors to your form.

## Basic Server Error Handling

When your server returns validation errors, you can apply them to the form using `setErrors`:

```ts
const form = useNotForm({
  schema,
  async onSubmit(values) {
    try {
      const response = await fetch('/api/submit', {
        method: 'POST',
        body: JSON.stringify(values),
      })

      if (!response.ok) {
        const data = await response.json()
        
        // Apply server errors to the form
        form.setErrors(data.errors)
        return
      }

      // Success!
      console.log('Form submitted successfully')
    } catch (error) {
      console.error('Submission error:', error)
    }
  },
})
```

## Error Format

The `setErrors` method accepts an object where keys are field paths and values are error messages or arrays of error messages:

```ts
// Single error per field
form.setErrors({
  email: 'This email is already registered',
  username: 'Username is taken',
})

// Multiple errors per field
form.setErrors({
  email: ['Invalid format', 'Already registered'],
  password: ['Too short', 'Must contain a number'],
})
```

## Nested Field Errors

Server errors work with nested field paths using dot notation:

```ts
form.setErrors({
  'user.email': 'This email is already registered',
  'user.name': 'Name is required',
})
```

## Clearing Server Errors

Server errors are cleared automatically when the user modifies the corresponding field. This is handled by NotForm's dirty tracking.

If you need to manually clear errors:

```ts
// Clear all errors
form.setErrors({})

// Clear errors for a specific field
form.clearErrors('email')
```

## Combining Client and Server Validation

NotForm seamlessly combines client-side validation (from your schema) with server-side validation:

1. **Before submission** - Client-side validation runs based on your validation mode
2. **On submission** - The form is validated again
3. **After submission** - Server errors are applied if the backend rejects the data

```ts
const form = useNotForm({
  schema,
  async onSubmit(values) {
    // Client-side validation already passed
    // Submit to server
    const response = await fetch('/api/submit', {
      method: 'POST',
      body: JSON.stringify(values),
    })

    if (!response.ok) {
      const data = await response.json()
      // Apply server-side errors
      form.setErrors(data.errors)
      return
    }

    // Success!
  },
})
```

## Global Server Errors

Sometimes servers return errors that aren't tied to a specific field (like "Rate limit exceeded"). You can handle these separately:

```ts
const form = useNotForm({
  schema,
  async onSubmit(values) {
    try {
      const response = await fetch('/api/submit', {
        method: 'POST',
        body: JSON.stringify(values),
      })

      if (!response.ok) {
        const data = await response.json()
        
        if (data.fieldErrors) {
          form.setErrors(data.fieldErrors)
        }
        
        if (data.globalError) {
          // Handle global errors separately
          console.error(data.globalError)
          showGlobalError(data.globalError)
        }
        return
      }
    } catch (error) {
      console.error('Submission error:', error)
    }
  },
})
```

## Best Practices

- **Match server error paths to your schema** - Use the same field paths in your server response as in your schema
- **Clear errors on user interaction** - NotForm does this automatically via dirty tracking
- **Provide clear error messages** - Server error messages should be user-friendly
- **Handle network errors gracefully** - Show appropriate feedback when the server is unreachable
