`<NotField>`{lang="vue"} is a renderless component that connects an individual field to NotForm's validation and state management.

It provides the field's current state, validation errors, a validation method, and event handlers that can be bound to native inputs or custom form components.

## Usage

A typical field combines the slot props with a form input and `<NotMessage>`{lang="vue"}.

## API

### Props

::field-group
  :::field{name="path" type="Paths<TSchema>" required}
  Dot path of this field. It identifies the value managed by the field.

  <br><br>

  Single fields use a single property name:

  ```vue
  <template>
    <NotField path="email">
      ...
    </NotField>
  </template>
  ```

  Nested fields use dot notation:

  ```vue
  <template>
    <NotField path="user.email">
      ...
    </NotField>
  </template>
  ```

  The same path is exposed through the default slot and can be used for labels, IDs, messages, and other field-specific elements.
  :::

  :::field{name="form" type="NotFormAPI<TSchema>"}
  Form instance. Overrides `<NotForm>`{lang="vue"} inject.

  <br><br>

  By default, `<NotField>`{lang="vue"} uses the form instance provided by a surrounding `<NotForm>`{lang="vue"}.

  <br><br>

  You can explicitly provide a form instance when needed:

  ```vue
  <template>
    <NotField
      v-slot="{ events }"
      :form="form"
      path="email"
    >
      <input v-bind="events">
    </NotField>
  </template>
  ```

  An explicit `form`{lang="ts-type"} takes priority over the form provided by a `<NotForm>`{lang="vue"} ancestor.

  <br><br>

  This is also required when using `<NotField>`{lang="vue"} as a standalone field outside of a `<NotForm>`{lang="vue"}.
  :::

  :::field{name="validateOn" type="Partial<Record<ValidationTrigger, boolean>>"}
  Validation triggers merged over defaults: `{ onBlur: true, onChange: true }`{lang="ts-type"}.

  <br><br>

  This allows individual validation triggers to be overridden for a field.

  <br><br>

  Only the triggers you specify are overridden; all other trigger settings remain unchanged.

  ```vue
  <template>
    <NotField
      path="username"
      :validate-on="{ onInput: true }"
    />
  </template>
  ```

  For example, in addition to the defaults, the field above will additionally validate on input.
  :::

  :::field{name="validationMode" type="'eager' | 'lazy'"}
  Controls how aggressively a field revalidates after it's been touched: `lazy`{lang="ts-type"} waits for the next blur or submit, `eager`{lang="ts-type"} also revalidates as the user types.

  <br><br>

  Defaults to `eager`{lang="ts-type"}.

  <br><br>

  In `eager`{lang="ts-type"} mode, once a field has an issue, it revalidates on every change/input event (subject to `validateOn`{lang="ts-type"} and `debounce`{lang="ts-type"}) so the error can clear as soon as the user fixes it. Until a field is invalid, change/input events are ignored — validation only starts once blur or submit produces the first issue.

  <br><br>

  In `lazy`{lang="ts-type"} mode, validation only runs on blur and submit, no matter how many issues are present. This produces less noise for fields where feedback on every keystroke isn't wanted.

  :::field{name="debounce" type="number"}
  Delays input- and change-triggered validation until the user stops interacting with the field for the specified number of milliseconds.

  <br><br>

  Omit or set to `0`{lang="ts-type"} to disable.

  <br><br>

  This is particularly useful for asynchronous validation, where validating on every keystroke could result in excessive requests.

  ```vue
  <template>
    <NotField
      v-slot="{ events }"
      path="username"
      :debounce="400"
    >
      <input
        v-model="form.values.username"
        v-bind="events"
      >
    </NotField>
  </template>
  ```

    ::note
    Blur and submit-triggered validation are always run immediately and are never delayed by `debounce`{lang="ts-type"}.

### Slots

#### `default`{lang="ts-type"}
The default slot receives the complete field state and event handlers.

```vue
<template>
  <NotField
    v-slot="slotProps"
    path="email"
  >
    ...
  </NotField>
</template>
```

::field-group
  :::field{name="path" type="string"}
  Dot path of this field.

  <br><br>

  Useful for labels, inputs, IDs, messages, and other field-specific elements.

  ```vue
  <template>
    <NotField
      v-slot="{ path }"
      path="email"
    >
      <label :for="path">Email</label>
      <input :id="path">
    </NotField>
  </template>
  ```
  :::

  :::field{name="errors" type="Array<Issue>"}
  Validation issues for this field path.

  <br><br>

  It contains all validation issues reported for the field during the most recent validation run.

  ```vue
  <template>
    <NotField
      v-slot="{ errors }"
      path="email"
    >
      <input v-model="form.values.email">

      <ul v-if="errors.length > 0">
        <li
          v-for="error in errors"
          :key="error.message"
        >
          {{ error.message }}
        </li>
      </ul>
    </NotField>
  </template>
  ```
  :::

  :::field{name="isValid" type="boolean"}
  Whether this field has no issues.

  <br><br>

  It is `true`{lang="ts-type"} if the field has no issues and `false`{lang="ts-type"} otherwise.

  ```vue
  <template>
    <NotField
      v-slot="{ isValid }"
      path="email"
    >
      <span v-if="isValid">Valid</span>
    </NotField>
  </template>
  ```
  :::

  :::field{name="isTouched" type="boolean"}
  Whether the user has interacted with this field.

  <br><br>

  This can be useful for displaying validation feedback only after the user has interacted with the field:

  ```vue
  <template>
    <NotField
      v-slot="{ isTouched, isValid, events }"
      path="email"
    >
      <input
        v-model="form.values.email"
        v-bind="events"
      >

      <p v-if="isTouched && !isValid">
        Please enter a valid email address.
      </p>
    </NotField>
  </template>
  ```
  :::

  :::field{name="isDirty" type="boolean"}
  Whether the value differs from the baseline.

  ```vue
  <template>
    <NotField
      v-slot="{ isDirty }"
      path="email"
    >
      <span v-if="isDirty">Unsaved changes</span>
    </NotField>
  </template>
  ```
  :::

  :::field{name="isValidating" type="boolean"}
  Whether this field is currently validating.

  ```vue
  <template>
    <NotField
      v-slot="{ isValidating }"
      path="username"
    >
      <span v-if="isValidating">
        Checking username...
      </span>
    </NotField>
  </template>
  ```
  :::

  :::field{name="events" type="Record<ExcludeStrict<ValidationTrigger, 'onMount'>, () => void>"}
  Handlers to bind to the input.

  <br><br>

  These handlers are used to track field interaction and trigger validation.

  - **Binding all events:**

  For native inputs, the simplest approach is to spread the handlers:

  ```vue
  <template>
    <NotField
      v-slot="{ events, path }"
      path="email"
    >
      <label :for="path">Email</label>

      <input
        :id="path"
        v-model="form.values.email"
        v-bind="events"
        type="email"
      >
    </NotField>
  </template>
  ```

  - **Binding individual events:**

  For custom components, bind the relevant handlers individually:

  ```vue
  <template>
    <NotField
      v-slot="{ events }"
      path="country"
    >
      <CustomCombobox
        @focusout="events.onBlur"
        @pick="events.onChange"
      />
    </NotField>
  </template>
  ```
    ::note
    The handlers don't require the original DOM event as an argument. They simply notify `<NotField>`{lang="vue"} that the corresponding interaction occurred.

  :::
