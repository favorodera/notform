`<NotForm>`{lang="vue"} is the root component that wraps your form. It provides the form instance to all descendant field components via Vue's `provide`{lang="ts-type"}/`inject`{lang="ts-type"}, so you don't need to pass a `form`{lang="ts-type"} prop to every `<NotField>`{lang="vue"} and `<NotArrayField>`{lang="vue"} individually, and it wires up the native `submit`{lang="ts-type"} and `reset`{lang="ts-type"} events on your behalf.

::note
`<NotForm>`{lang="vue"} is a convenience, not a requirement. Every field component also accepts an explicit `form`{lang="ts-type"} prop, which takes priority over `<NotForm>`{lang="vue"}'s context and is required if you render fields without a `<NotForm>`{lang="vue"} ancestor at all.
::

Under the hood, `<NotForm>`{lang="vue"} renders a native `<form>`{lang="vue"} element, and it automatically:

- Prevents the browser's default full-page navigation on `submit`{lang="ts-type"} and default field-clearing on `reset`{lang="ts-type"} — both would otherwise happen before any of your own logic runs, so this hands control back to you.
- Provides the `form`{lang="ts-type"} instance to descendant `<NotField>`{lang="vue"} and `<NotArrayField>`{lang="vue"} components.

Because the underlying element is native, it does **not** clear validation errors or restore values by itself — that's what `form.reset()`{lang="ts-type"} does. `<NotForm>`{lang="vue"} only stops the browser from doing its own, separate reset first. This is why the usage example below still binds `@submit="form.submit"`{lang="ts-type"} and `@reset="form.reset()"`{lang="ts-type"} explicitly: `<NotForm>`{lang="vue"} clears the way for those calls to run, but doesn't make them for you.

Because it's still a real `<form>`{lang="vue"} element, other native behavior keeps working as expected:

- Native form attributes like `action`{lang="ts-type"}, `method`{lang="ts-type"}, and `enctype`{lang="ts-type"} can be set directly on `<NotForm>`{lang="vue"} and pass through.
- Submitting with the keyboard (pressing Enter in a text field) and assistive technology both work the same as with a plain `<form>`{lang="vue"}.
- Native HTML validation attributes (`required`{lang="ts-type"}, `pattern`{lang="ts-type"}, `minlength`{lang="ts-type"}, and so on) still trigger the browser's built-in validation UI alongside NotForm's own. If you only want NotForm's validation messages to show, add `novalidate`{lang="vue"} to suppress the browser's.

## Usage

A typical form setup involves passing a form instance to `<NotForm>`{lang="vue"} via the `form`{lang="ts-type"} prop, then wrapping your fields in its default slot.

```vue
<script setup lang="ts">
import { NotForm, useNotForm } from 'notform'
import { z } from 'zod'

const schema = z.object({
  email: z.email('Invalid email'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
})

const form = useNotForm({
  onSubmit(values) {
    console.log('Form submitted:', values)
  },
  schema,
})
</script>

<template>
  <NotForm
    :form="form"
    @submit="form.submit"
    @reset="form.reset()"
  >
    <!-- Form fields go here -->
    <button
      type="submit"
      :disabled="form.isSubmitting"
    >
      Submit
    </button>

    <button type="reset">
      Reset
    </button>
  </NotForm>
</template>
```

## API

### Props

::field-group
  :::field{name="form" type="NotFormAPI<TSchema>" required}
  Form instance provided to descendant field components.

  <br><br>

  This is the same instance returned by [`useNotForm`{lang="ts-type"}](/composables/use-not-form). `<NotForm>`{lang="vue"} makes it available to every `<NotField>`{lang="vue"} and `<NotArrayField>`{lang="vue"} beneath it, without needing to repeat it as a prop on each one.
  :::
::

### Slots

#### `default`{lang="ts-type"}
The default slot for housing your form fields.

```vue
<template>
  <NotForm
    :form="form"
    @submit="form.submit"
    @reset="form.reset()"
  >
    <!-- Form fields go here -->
  </NotForm>
</template>
```

::note
Unlike `<NotField>`{lang="vue"} and `<NotArrayField>`{lang="vue"}, this slot receives no slot props — there's no `v-slot`{lang="ts-type"} to bind here. `<NotForm>`{lang="vue"} only provides the `form`{lang="ts-type"} instance to descendants via context; to read form-level state like `form.isSubmitting`{lang="ts-type"} or `form.isValid`{lang="ts-type"} inside the slot, reference the `form`{lang="ts-type"} instance directly, as shown in the Usage example above.
::
