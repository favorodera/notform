`<NotMessage>`{lang="vue"} is a small component for displaying the validation error message for a specific field.

It automatically displays the first active validation error for the field and renders nothing when the field has no validation errors.

## Usage

The most common usage is alongside a `<NotField>`{lang="vue"}:

```vue
<template>
  <NotField
    v-slot="{ events, path }"
    path="email"
  >
    <label :for="path">Email</label>

    <input
      :id="path"
      v-model="form.values.email"
      v-bind="events"
      type="email"
    >

    <NotMessage :path="path" />
  </NotField>
</template>
```

::tip
When validation fails, `<NotMessage>`{lang="vue"} displays the first validation error associated with `email`{lang="ts-type"} field and nothing when there are no active validation errors.
::

### Displaying Multiple Errors

`<NotMessage>`{lang="vue"} intentionally displays only the first active validation error.

If you need to display every validation issue for a field, use the field's `errors` slot prop instead:

```vue
<template>
  <NotField
    v-slot="{ events, path, errors }"
    path="email"
  >
    <input
      :id="path"
      v-model="form.values.email"
      v-bind="events"
      type="email"
    >

    <div v-if="errors.length > 0">
      <p
        v-for="(error, index) in errors"
        :key="index"
      >
        {{ error.message }}
      </p>
    </div>
  </NotField>
</template>
```

This gives you access to the complete validation issues or errors rather than only the first message.

## API

### Props

::field-group
  :::field{name="path" type="Paths<TSchema>" required}
  Field path whose first error message is shown.

  <br><br>

  It supports the same dot-separated paths used by `<NotField>`{lang="vue"}:

  ```vue
  <template>
    <NotMessage path="email" />
  </template>
  ```

  For nested fields:

  ```vue
  <template>
    <NotMessage path="user.email" />
  </template>
  ```
  :::

  :::field{name="form" type="NotFormAPI<TSchema>"}
  Form instance. Overrides `<NotForm>`{lang="vue"} inject.

  <br><br>

  By default, `<NotMessage>`{lang="vue"} uses the form instance provided by a surrounding `<NotForm>`{lang="vue"}.

  <br><br>

  You can explicitly provide a form instance when needed:

  ```vue
  <template>
    <NotMessage
      :form="form"
      path="email"
    />
  </template>
  ```

  An explicit `form`{lang="ts-type"} takes priority over the form provided by a `<NotForm>`{lang="vue"} ancestor.

  <br><br>

  This is also required when using `<NotMessage>`{lang="vue"} as a standalone component outside of a `<NotForm>`{lang="vue"}.
  :::

  :::field{name="as" type="Component | string"}
  Root element or component - defaults to `'span'`{lang="ts-type"}.

  <br><br>

  Use to change the rendered element:

  ```vue
  <template>
    <NotMessage
      path="email"
      as="p"
    />
  </template>
  ```

  Or provide a component - useful when your application has a shared component for validation messages:

  ```vue
  <template>
    <NotMessage
      path="email"
      :as="ErrorMessage"
    />
  </template>
  ```
  :::
::

### Slots

#### `default`{lang="ts-type"}
The default slot receives the current error message.

```vue
<template>
  <NotMessage
    v-slot="slotProps"
    path="email"
  >
    ...
  </NotMessage>
</template>
```

::field-group
  :::field{name="message" type="string"}
  The first active error message for the specified field.

  <br><br>

  If no error is present for the field, this value is `undefined`.

  ```vue
  <template>
    <NotMessage
      v-slot="{ message }"
      path="email"
    >
      <span>{{ message }}</span>
    </NotMessage>
  </template>
  ```

  ::::tip
  Normally, you do not need to check for `message` yourself because `<NotMessage>` renders nothing when there is no error.
  ::::

  This also allows control over the message markup like adding custom classes, icons and  wrappers.

  ```vue
  <template>
    <NotField
      v-slot="{ events, path }"
      path="email"
    >
      <input
        :id="path"
        v-model="form.values.email"
        v-bind="events"
        type="email"
      >
  
      <NotMessage
        v-slot="{ message }"
        :path="path"
        as="p"
      >
        <span class="flex items-center gap-2">
          <Icon name="tabler:alert-circle" />
          {{ message }}
        </span>
      </NotMessage>
    </NotField>
  </template>
  ```
  :::
::
