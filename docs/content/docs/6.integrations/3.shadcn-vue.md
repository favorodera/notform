shadcn-vue copies component source into your project, so the exact props depend on the version you installed. The mappings below follow the pattern in [Custom components](/docs/integrations/custom-components). Check your local component files if a binding differs.

## Resolve the naming conflict

Recent shadcn-vue releases include `Field` and `FieldError` components. NotForm exports components with the same names. Rename one set at the import.

::code-group
```vue [Vue]
<script setup lang="ts">
import { Form, Field as NotField, FieldError as NotFieldError, useForm } from 'notform'
import { Field, FieldError, FieldLabel } from '@/components/ui/field'
</script>
```

```ts [Nuxt (module aliases)]
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@notform/nuxt', 'shadcn-vue/nuxt'],
  notform: {
    aliases: { Field: 'NotField', FieldError: 'NotFieldError' },
  },
})
```
::

The examples below use `NotField` for NotForm and `Field` for shadcn-vue.

## Text input

::code-collapse
```vue
<script setup lang="ts">
import { Form, Field as NotField, useForm } from 'notform'
import { z } from 'zod'
import { Button } from '@/components/ui/button'
import { Field, FieldError, FieldLabel } from '@/components/ui/field'
import { Input } from '@/components/ui/input'

const form = useForm({
  initialValues: { email: '' },
  onSubmit: (data) => {
    return console.log(data)
  },
  schema: z.object({
    email: z.email('Enter a valid email address.')
  }),
})
</script>

<template>
  <Form
    :form="form"
    novalidate
    class="space-y-4"
  >
    <NotField
      v-slot="{ field }"
      :field="form.field('email')"
    >
      <Field :data-invalid="!field.isValid">
        <FieldLabel :for="field.path">
          Email
        </FieldLabel>

        <Input
          :id="field.path"
          v-model="field.model"
          v-bind="field.events"
          type="email"
          :aria-invalid="!field.isValid"
        />

        <FieldError
          v-if="!field.isValid"
          :errors="field.errors"
        />
      </Field>
    </NotField>

    <Button
      type="submit"
      :disabled="form.isSubmitting"
    >
      Submit
    </Button>
  </Form>
</template>
```
::

`field.errors` is an array of issues that each have a `message`, which is the shape shadcn-vue's `FieldError` renders. If your version of `FieldError` expects something else, render the message directly:

```vue
<template>
  <p
    v-if="field.errors[0]"
    class="text-destructive text-sm"
  >
    {{ field.errors[0].message }}
  </p>
</template>
```

If your shadcn-vue version predates the Field components, use `Label` and NotForm's own `FieldError` instead.

## Checkbox

Recent shadcn-vue checkboxes use `v-model`. Older versions used `checked` and `update:checked`, so match what your local file declares.

```vue
<template>
  <NotField
    v-slot="{ field }"
    :field="form.field('acceptTerms')"
  >
    <div class="flex items-center gap-2">
      <Checkbox
        :id="field.path"
        v-model="field.model"
        @update:model-value="field.events.onChange"
      />

      <Label :for="field.path">I accept the terms</Label>
    </div>
  </NotField>
</template>
```

If the checkbox can be in an indeterminate state, its value is not a plain boolean, so your schema must accept that.

## Select

The trigger is the focusable element, so report blur from it.

```vue
<template>
  <NotField
    v-slot="{ field }"
    :field="form.field('country')"
  >
    <label :for="field.path">Country</label>

    <Select
      :id="field.path"
      v-model="field.model"
      @update:model-value="field.events.onChange"
    >
      <SelectTrigger
        :id="field.path"
        @blur="field.events.onBlur"
      >
        <SelectValue placeholder="Choose a country" />
      </SelectTrigger>

      <SelectContent>
        <SelectItem
          v-for="country in countries"
          :key="country.code"
          :value="country.code"
        >
          {{ country.name }}
        </SelectItem>
      </SelectContent>
    </Select>
  </NotField>
</template>
```
