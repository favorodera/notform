AI assistants are fast at writing form code, and just as quick to invent APIs that do not exist. NotForm's API is small but specific, so an assistant working from memory will often reach for names from other libraries.

NotForm gives assistants three ways to work from the real documentation.

| Resource | What it is | Best for |
| --- | --- | --- |
| [`llms.txt`](/docs/ai/llms-txt) | An index of every documentation page with a one-line description | Letting an assistant discover which pages exist |
| [Page Markdown](/docs/ai/llms-txt#read-a-single-page) | Any documentation page as clean Markdown | Loading exactly the pages a task needs |
| [`llms-full.txt`](/docs/ai/llms-txt#the-full-documentation) | The whole documentation in one file | Broad tasks, or tools that cannot follow links |
| [The agent skill](/docs/ai/agent-skill) | A short set of instructions that routes an agent to the right pages | Making the agent do all of the above on its own |

## Quick start

1. **Install the skill.** Copy the `notform` skill into your project so your assistant loads it automatically. See [Agent skill](/docs/ai/agent-skill#install).
2. **Ask for what you need.** Describe the form in plain words. The skill makes the assistant read the matching pages before it writes code.
3. **Review against the docs.** Ask the assistant which pages it used. If something it wrote is not in those pages, it is a guess.

No skill support? Paste `https://notform.favorodera.dev/llms.txt` into the conversation and ask the assistant to read the pages relevant to your task before writing code.

## What assistants get right and wrong

Assistants do well when the docs are in front of them. These are the mistakes the documentation and skill are designed to prevent:

- using `path` props or form context from NotForm v3 instead of explicit field instances;
- using `index` instead of `item.id` as an array key;
- mutating arrays directly instead of through `ArrayField` methods;
- expecting `form.setValue` or `field.model` writes to validate;
- passing field configuration on every render and expecting it to apply;
- mixing NotForm with another form library on the same form.
