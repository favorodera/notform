---
title: Reka UI
description: Use NotForm with Reka UI's unstyled primitives such as checkboxes, selects, switches, and radio groups.
---

Reka UI provides unstyled, accessible primitives. NotForm provides the form state. Together they let you build a fully custom design system.

Reka UI components emit `update:modelValue` when a value changes, so most bindings follow the pattern in [Custom components](/docs/integrations/custom-components): `v-model` plus an explicit `onChange`, and `onBlur` from whichever element receives focus. Check Reka UI's documentation for your version's exact parts and events.

## Checkbox

::code-collapse
```vue
<script setup lang="ts">
import { CheckboxIndicator, CheckboxRoot } from 'reka-ui'
</script>

<template>
  <Field
    v-slot="{ field }"
    :field="form.field('acceptTerms')"
  >
    <label
      class="flex items-center gap-2"
      :for="field.path"
    >
      <CheckboxRoot
        :id="field.path"
        v-model="field.model"
        class="checkbox"
        @update:model-value="field.events.onChange"
        @blur="field.events.onBlur"
      >
        <CheckboxIndicator>✓</CheckboxIndicator>
      </CheckboxRoot>
      I accept the terms
    </label>

    <FieldError :errors="field" />
  </Field>
</template>
```
::

Use a `boolean` in your schema. If you enable the indeterminate state, the model can also be `'indeterminate'`.

## Select

Report change on selection, and blur when the list closes.

::code-collapse
```vue
<script setup lang="ts">
import {
  SelectContent, SelectItem, SelectItemText, SelectPortal,
  SelectRoot, SelectTrigger, SelectValue, SelectViewport,
} from 'reka-ui'
</script>

<template>
  <Field
    v-slot="{ field }"
    :field="form.field('country')"
  >
    <SelectRoot
      v-model="field.model"
      @update:model-value="field.events.onChange"
      @update:open="(open) => {
        if (!open) {
          field.events.onBlur()
        }
      }"
    >
      <SelectTrigger
        :id="field.path"
        :aria-invalid="!field.isValid"
      >
        <SelectValue placeholder="Choose a country" />
      </SelectTrigger>

      <SelectPortal>
        <SelectContent>
          <SelectViewport>
            <SelectItem
              v-for="country in countries"
              :key="country.code"
              :value="country.code"
            >
              <SelectItemText>{{ country.name }}</SelectItemText>
            </SelectItem>
          </SelectViewport>
        </SelectContent>
      </SelectPortal>
    </SelectRoot>

    <FieldError :errors="field" />
  </Field>
</template>
```
::

## Radio group

```vue
<template>
  <RadioGroupRoot
    v-model="field.model"
    @update:model-value="field.events.onChange"
  >
    <label
      v-for="plan in ['free', 'pro']"
      :key="plan"
      :for="`${field.path}-${plan}`"
      class="flex items-center gap-2"
    >
      <RadioGroupItem
        :id="`${field.path}-${plan}`"
        :value="plan"
      />
      {{ plan }}
    </label>
  </RadioGroupRoot>
</template>
```

## Tips

- Primitives are unstyled, so wrap them once in your own components and pass a NotForm field as a prop. See [the reusable wrapper pattern](/docs/integrations/custom-components#a-reusable-field-wrapper).
- Match the schema to the model type the primitive emits. Checkboxes and switches emit booleans, selects emit the item's `value`, and sliders emit arrays of numbers.
- Reka UI primitives portal their popups. Blur on the trigger therefore does not fire while the list is open, which is why the select example reports blur from `update:open`.
