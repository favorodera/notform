This guide builds a small sign-in form using Vue 3, Zod, and NotForm.

The goal is to show the relationship between the schema, the form instance, and the field components. Once that pattern makes sense, you can use the same structure with other validators and UI systems.

## 1. Define the schema

Start with the data your form accepts.

```ts
import { z } from 'zod'

const schema = z.object({
  email: z.email('Enter a valid email'),
  password: z.string().min(8, 'At least 8 characters'),
})
```

The schema controls validation and provides the types used by NotForm.

## 2. Create the form

Pass the schema to `useForm`.

```ts
const form = useForm({
  onSubmit(values) {
    console.log('Submitted:', values)
  },
  schema,
})
```

Provide `initialValues` when you want explicit starting data:

```ts
const form = useForm({
  initialValues: {
    email: '',
    password: '',
  },
  schema,
})
```

## 3. Add the form component

`<Form>` renders a native `<form>`, provides context to its descendant fields, and automatically connects native submit/reset events to the form instance.

```vue
<template>
  <Form :form="form">
    <!-- fields -->

    <button
      type="submit"
      :disabled="form.isSubmitting"
    >
      {{ form.isSubmitting ? 'Submitting…' : 'Submit' }}
    </button>

    <button type="reset">Reset</button>
  </Form>
</template>
```

You do not need to bind `@submit="form.submit"` or `@reset="form.reset()"` when using `<Form>`. It calls those methods internally and prevents the browser's native submit navigation and reset behavior.

## 4. Connect a field

`<Field>` is renderless. It gives you the field path, field state, errors, and event handlers through its default slot.

```vue
<template>
  <Field
    v-slot="{ events, path }"
    path="email"
  >
    <label :for="path">Email</label>

    <input
      :id="path"
      v-model="form.values.email"
      v-bind="events"
      type="email"
      autocomplete="email"
    >

    <Error :path="path" />
  </Field>
</template>
```

You still own the input element. `v-model` updates the value, while `events` connects that input to NotForm's touched and validation lifecycle.

## 5. Use submission state

Submission state is reactive, so use it directly in the template. A submit attempt sets `isSubmitted` and increments `submitCount`; field and array touched indicators then reflect that the form has been submitted.

```vue
<template>
  <button
    type="submit"
    :disabled="form.isSubmitting"
  >
    {{ form.isSubmitting ? 'Submitting…' : 'Submit' }}
  </button>
</template>
```

The architecture is deliberately small:

| Part | Description |
| ---  | --- |
| `schema` | Validation and types |
| `useForm` | Values and lifecycle |
| `Form` | Native form, context and submit/reset wiring |
| `Field` | Field state and events |
| `Error` | First field error |
