NotForm's official Nuxt integration is published as `@notform/nuxt`.

The module auto-imports the core composable and components. It does not change the form API or install a validator for you.

## Install

Install the module and a Standard Schema-compatible validator, for example Zod:

::code-group
```bash [npm]
npm install @notform/nuxt zod
```
```bash [pnpm]
pnpm add @notform/nuxt zod
```
```bash [yarn]
yarn add @notform/nuxt zod
```
```bash [bun]
bun add @notform/nuxt zod
```
::

Register the module in `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  modules: ['@notform/nuxt'],
})
```

## Auto-imports

The module makes these APIs available without imports in Nuxt components:

| API | Kind | Purpose |
| --- | --- | --- |
| `useForm` | composable | Create the form instance |
| `Form` | component | Render the native form, provide context, and wire submit/reset events |
| `Field` | component | Connect an individual field |
| `ArrayField` | component | Manage repeatable fields and nested state |
| `Error` | component | Render a field's first error message |

Your validator is still a normal application dependency:

```vue
<script setup lang="ts">
import { z } from 'zod'

const schema = z.object({
  email: z.email(),
})

const form = useForm({
  schema,
})
</script>
```

## Rename auto-imports

Use the `notform.aliases` option to register selected exports under your own names. The alias map accepts `Form`, `Field`, `ArrayField`, `Error`, and `useForm`.

```ts
export default defineNuxtConfig({
  modules: ['@notform/nuxt'],
  notform: {
    aliases: {
      Form: 'AppForm',
      useForm: 'useAppForm',
    },
  },
})
```

Aliases change the names Nuxt auto-imports; they do not rename the exports in the core `notform` package.

## Form instances and server rendering

The Nuxt module only wires imports and components into the Nuxt application. Form state belongs to the instance created by `useForm`. Create form instances in normal Vue setup code; do not keep one form instance in module scope and reuse it across requests.

## What the module does not do

The module does not:

- choose a validation library
- add styling or input components
- replace the core NotForm API
- persist form state between requests

It is an integration layer, not a second form library.
