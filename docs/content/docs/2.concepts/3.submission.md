title: Submission
description: Understand NotForm's submit lifecycle and how validation and onSubmit work together.
---

Submission in NotForm is a small lifecycle around validation.

The `<Form>` component binds the native submit event to `form.submit()` for you. The form instance prevents the browser's default navigation, validates the form, and calls your submit handler only when validation succeeds.

## Basic submission

```vue
<template>
  <Form :form="form">
    <!-- fields -->

    <button
      type="submit"
      :disabled="form.isSubmitting"
    >
      {{ form.isSubmitting ? 'Submitting…' : 'Submit' }}
    </button>
  </Form>
</template>
```

## Submission lifecycle

`form.submit()` performs these steps:

1. prevents the browser's default submit when called with an event
2. ignores the attempt if another submission is already in progress
3. increments `submitCount` and marks the form as submitted
4. validates the complete form
5. stores validation issues and skips `onSubmit` when invalid
6. clears current errors and calls `onSubmit` with validated output when valid
7. keeps `isSubmitting` active while `onSubmit` runs

## `isSubmitting`

Use `form.isSubmitting` to disable repeated submission or display progress:

```vue
<template>
  <button
    type="submit"
    :disabled="form.isSubmitting"
  >
    {{ form.isSubmitting ? 'Saving…' : 'Save' }}
  </button>
</template>
```

A second submit call while one submission is running is ignored and does not increment `submitCount`. `isSubmitted` remains true until `reset()` clears the submission tracking.

## Successful submission

`onSubmit` receives the schema's **output** type.

```ts
const form = useForm({
  async onSubmit(data) {
    await saveUser(data)
  },
  schema,
})
```

This matters for schemas that coerce or transform their input.

## Invalid submission

When validation returns issues:

- the issues replace `form.errors`
- `onSubmit` is not called
- `isSubmitting` returns to false after the lifecycle finishes

A submit attempt sets `isSubmitted`. Field and array `isTouched` flags therefore report `true` after the first attempt, even though the form does not need to enumerate and mark every leaf path individually.

## Programmatic submission

You can also submit from code:

```ts
await form.submit()
```

When called with a native event, `submit()` calls `preventDefault()` immediately.

## Native form behavior

`<Form>` wires both native events to the form instance: it passes the submit event to `form.submit()` and prevents the browser's reset behavior before calling `form.reset()`.

You can also use the form instance without `<Form>`. In that case, pass `:form="form"` directly to each field component that needs it and wire `form.submit` / `form.reset` yourself if you use a native form element.

## Server errors

Server-side validation belongs to the same error state as schema validation.

After an API request fails, use `form.setError()` to attach issues to fields or to the form itself.

See [Server Errors](/docs/concepts/server-errors).

## Reset after success

NotForm does not automatically make submitted values the new clean baseline.

If your application wants the saved values to become the new baseline:

```ts
form.reset(savedValues)
```

That clears dirty and touched state and makes those values the next reset target.
