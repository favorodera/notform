---
title: Form
description: Render a native form, provide form context, and connect submit and reset events.
---

`<Form>` renders a native `<form>` and provides its form instance to descendant components.

It wires native submit and reset events to the form instance automatically: submit runs `form.submit(event)`, and reset prevents the browser's native reset before calling `form.reset()`. You do not need to add `@submit` or `@reset` for NotForm's normal lifecycle.

## Usage

```vue
<template>
  <Form :form="form">
    <!-- fields -->

    <button type="submit">
      Save
    </button>

    <button type="reset">
      Reset
    </button>
  </Form>
</template>
```

`<Form>` is optional. When you do not use it, pass `:form="form"` directly to each `<Field>`, `<ArrayField>`, and `<Error>` that needs the instance.

## Native form behavior

Because `<Form>` renders a native `<form>`, normal form attributes remain available:

```vue
<template>
  <Form
    :form="form"
    method="post"
    action="/account"
    novalidate
  >
    ...
  </Form>
</template>
```

Use `novalidate` when NotForm should provide the only validation feedback. Attributes such as `method`, `action`, `class`, and `id` are forwarded to the native form element.

## Context

Descendant `<Field>`, `<ArrayField>`, and `<Error>` components can resolve the nearest form automatically.

An explicit `form` prop on one of those components takes priority over injected context.

## Props

| Prop | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `form` | `UseFormReturn<TSchema>` | Yes | — | Instance returned by `useForm()` and provided to descendants |

## Slots

| Slot | Props | Description |
| --- | --- | --- |
| `default` | — | Form content rendered inside the native `<form>` |

## Submit and reset

On submit, `<Form>` calls `form.submit()` with the native event. The form instance prevents the default browser navigation, validates the full form, and calls `onSubmit` only when validation succeeds.

On reset, `<Form>` prevents the browser's default reset and restores the NotForm baseline, including values, baseline errors, touched state, and submission state. A native button with `type="reset"` is enough to trigger this behavior.

You can also invoke `form.submit()` or `form.reset()` directly from application code. When handling a native form yourself instead of using `<Form>`, wire those methods to the native submit and reset events manually.
