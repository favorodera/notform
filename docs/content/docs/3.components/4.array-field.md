`<ArrayField>` exposes array items, stable render keys, aggregate state, and mutation methods through a renderless slot.

It exposes current items, stable keys, recursive aggregate state, and mutation methods while leaving the row markup entirely to you.

::caution
Always use `item.key` as the Vue `v-for` key. The current index describes position, not identity.
::

## Props

| Prop | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `path` | `Path<TSchema>` | Yes | — | Dot path of the array field; dynamic array-item paths are also accepted |
| `itemSchema` | `TItemSchema` | No | — | Optional schema used only for mutation value inference |
| `form` | `UseFormReturn<TSchema>` | No | Injected form | Explicit instance that takes priority over the nearest `<Form>` |

## `itemSchema`

`itemSchema` only supplies TypeScript inference for inserted and updated values. It is not used as a runtime validator.

The array is validated by the main form schema supplied to `useForm()`.

## Slot: `default`

| Prop | Type | Description |
| --- | --- | --- |
| `path` | `string` | Current array path |
| `items` | `ArrayFieldItem<TSchema>[]` | Items with `key`, `index`, and `path` |
| `errors` | `Issue[]` | Issues exactly at the array path |
| `isValid` | `boolean` | Whether the array and all descendants have no issues |
| `isTouched` | `boolean` | Whether the array or a descendant is touched, or the form has been submitted |
| `isDirty` | `boolean` | Whether the array or a descendant differs from baseline |
| `isValidating` | `boolean` | Whether the array or a descendant is validating |
| `append` | `(value) => void` | Add an item to the end |
| `prepend` | `(value) => void` | Add an item to the beginning |
| `insert` | `(index, value) => void` | Insert an item |
| `remove` | `(index) => void` | Remove an item |
| `update` | `(index, value) => void` | Replace an item without changing its key |
| `swap` | `(indexA, indexB) => void` | Exchange two items |
| `move` | `(from, to) => void` | Move an item |

## Mutation methods

### `append`

```ts
append({ email: '', name: '' })
```

Adds an item to the end and gives it a new stable key.

### `prepend`

```ts
prepend({ email: '', name: '' })
```

Adds an item to the beginning and remaps existing items' nested touched paths and validation issues.

### `insert`

```ts
insert(2, { email: '', name: '' })
```

The insertion position is clamped to the valid range. Non-integer indices are ignored, and nested touched paths and validation issues for later items are remapped.

### `remove`

```ts
remove(1)
```

Removes the item and its key, drops that item’s nested touched paths and validation issues, then remaps later items’ state paths as they shift left.

### `update`

```ts
update(1, {
  email: 'jane@example.com',
  name: 'Jane',
})
```

Replaces the value without changing the item's key or position.

### `swap`

```ts
swap(0, 1)
```

Exchanges the items and stable keys, and remaps nested touched paths and validation issues. Dirty state is derived by comparing values at each path with the reset baseline, so dirty flags can change after a reorder.

### `move`

```ts
move(0, 3)
```

Moves one item and shifts the items between the source and destination, remapping their nested touched paths and validation issues. The destination is clamped to the current array bounds; invalid source indices are ignored.

## Item identity

Use the item object rather than reconstructing paths from raw indexes when possible:

```vue
<template>
  <div
    v-for="item in items"
    :key="item.key"
  >
    <Field :path="`${item.path}.name`" />
  </div>
</template>
```

`item.path` always reflects the item's current index.

## Recursive state

The aggregate flags include the entire array subtree.

An error at:

```text
users.2.profile.email
```

makes `isValid` false for the `users` array even though `errors` is empty when the issue is not reported directly at `users`.

The same recursive rule applies to touched, dirty, and validating state.

## Direct array mutation

Avoid changing the array with `push()`, `splice()`, or direct index assignment when you need row identity and state preservation:

```ts
form.values.users.push(user)
```

Use the ArrayField methods instead:

```ts
append(user)
```

The mutation methods update values and keys and remap nested touched state and validation issues where the item positions change. Dirty state updates reactively from the current values and reset baseline.

## Async validation

Structural mutations invalidate older in-flight validation results. This prevents a stale response from being attached to a different item after a remove, insert, swap, or move.
